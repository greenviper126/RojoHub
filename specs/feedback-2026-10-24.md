# Feedback log, 2026-10-24 (agent session)

Logged only; nothing fixed until the go-ahead. Each item was checked against the code.

## Valid, to do

1. **MCP connection lost for a whole session when the service is down at session start.**
   `src/service/mcp.ts` is streamable HTTP served by the service itself, so a client that
   connects while the service is not running stays failed until `/mcp` reconnects.
   Idea: a small stdio launcher the agent config points at. It starts the service if it is
   down, retries, and answers "hub not running, starting it" instead of failing. Would make
   the `rojohub.mjs` fallback unnecessary. Touches `src/service/agentConfig.ts` (what is
   written into agent configs) and the uninstall path.
2. **One "get me ready" call.** `ensure(project, worktree, place)`: start if stopped,
   serve_here, open_place if none open, wait_for_studio, return the Studio place/window id.
   Idempotent. Composes existing hub operations.
3. **Studio state (idle / edit / playing) and a queue for edit-mode jobs.** Needs the plugin to
   report play state (a new optional message, so no `STUDIO_PROTOCOL` bump if older plugins can
   skip it). The queue lives in the service.
4. **`run_in_studio(script)` through the plugin**, so agents stop writing temp files into `src/`.
   New message type plugin-side; an optional new message needs no protocol bump. Needs a spec
   (security: runs arbitrary Luau in the user's Studio, so it should be opt-in).
5. **Sourcemap watcher: give up less easily.** It already restarts after 1 s and gives up after
   5 crashes in a minute (`SourcemapWatcher`), so the report's "TheLaundryShift left off" was a
   crash loop. Idea: after giving up, retry once after a longer pause (e.g. 30 s) instead of
   staying off for good, and surface it in `status`.
6. **Rojo crash after a branch switch in the main checkout.** Report says it crashed once
   before; not reproduced here. Needs the repro (see the rojo#1305 rule) before any fix.
7. **Structured status.** A JSON form of `status` (and `serve_here`) next to the text, for agents.
   Low cost, add alongside 1 and 2.

## Not valid / already there

- **Claims with owner and expiry, released when the agent ends** (report item 5): already exist.
  `hub.ts` keeps claims per slot with a 10-minute hold, renewed by each call, and `release`
  frees one. Only the unmet part is a quiet note in the panel "now serving X for agent Y",
  which is a small panel addition if wanted; releasing on agent exit is not possible from the
  service (it cannot see the agent end), so expiry stays the mechanism.

## Suggested order

1 and 2 first (most friction removed), then 7, then 3 and 4 as one Studio-plugin spec, then 5.

17. **MCP down** (their 10) = item 1. A small `rojohub` CLI with the same verbs is an

# Third batch (same day): Studio visibility, plugin dev host

## Valid, to do

19. **Plugin dev host** (their 1). Studio plugin loads plugin code Rojo syncs into ServerStorage and
    reloads it when Rojo pushes a change. Valid and useful for plugin projects, but it runs
    project code inside the user's Studio plugin context: opt-in per project, spec first, and it
    belongs with 4 (`run_in_studio`) in the Studio-plugin spec. Larger than it sounds
    (sandboxing, errors, unloading).
20. **One "verify in Studio" call** (their 3). Same call as `ensure` (2) plus a smoke step.
    Rojo-Hub can do serve_here + wait_for_studio + report; the script and screenshot parts
    come from 4 or the Roblox Studio MCP. Fold into 2 as an optional `then` step.
21. **Playtest and publish need an explicit human flag** (their 6). Rojo-Hub starts neither
    today, so nothing to guard now. Valid as a rule for 4 and 19: new Studio-side verbs ship
    off by default behind a setting.

## Not valid / already there

- **Viewport screenshot, Output log, run Luau in Edit, inspect** (their 2): the Roblox Studio
  MCP already provides these (screen_capture, get_console_output, execute_luau,
  inspect_instance). Not Rojo-Hub's job to duplicate; at most `run_in_studio` (4) for sessions
  without that MCP.
- **Throwaway test places / snapshot and restore** (their 4): Rojo-Hub does not own place
  state. Rojo overwrites synced instances anyway; unsynced junk would need Studio-side
  undo/save control that the plugin API does not offer safely. Dropped.
- **Auto-follow the agent's folder, release on session end** (their 5): the service cannot see
  an agent's cwd or its end (see first batch, claims). Visible state in VS Code is the panel note
  already logged under claims.
- **Simulated input** (their 7): out of scope for Rojo-Hub; Studio MCP has user_mouse_input.

## Order

19 and 21 ride with the Studio-plugin spec (3+4). 20 rides with 2.
